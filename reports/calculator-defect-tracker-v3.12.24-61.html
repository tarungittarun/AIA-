Detailed, commented defect tracker

Root-cause language is intentionally qualified. The runtime tests identify observable failures; they do not prove the internal implementation path.

DEF-324-01 · Chained repeating-decimal calculation loses precision

OPEN · P2

QA comment: This is a direct APK arithmetic mismatch on both distributed calculator packages. The UI shows a rounded quotient, and the next operation returns a value one unit in the tenth decimal place below the expected integer. The observed behavior is consistent with reusing rounded display text, but that is a hypothesis—not a source-level diagnosis.

Affected builds
MySpace 3.12.24 (61), app.space.one; MyCalc 1.0.22 (23), app.space.calc.
Reproduction
Enter 1 ÷ 3, evaluate, then multiply the displayed result by 3 and evaluate again.
Expected
1.
Observed
Both APKs displayed 0.3333333333 after the first step and 0.9999999999 after the second.
Evidence
TC-CALC-008, direct APK runtime, shard 3 of run 40321408355; both APKs have individual failure annotations.
Impact
Chained calculations involving repeating decimals can yield a visibly incorrect final answer; the same behavior occurred in both integrated and standalone calculator packages.
Suggested next step
Keep an unrounded numeric result/AST for subsequent operators and format only for display; add a regression test for the exact sequence on both APK variants. Confirm the implementation before assigning a root cause.
Regression note
The v3.12.21 report also recorded TC-008 failure for both APKs; the v3.12.24 direct run re-observed it.

DEF-324-02 · Exponent-formatted result cannot be continued with +1

OPEN · P2

QA comment: The 1015 result is shown in exponent notation; adding one to continue the calculation produces Error in both APKs. The probe is a blind large-number boundary check, not a literal guide step. It is consistent with the expression parser rejecting a display-formatted exponent, but the cause remains unconfirmed.

Affected builds
MySpace 3.12.24 (61) and standalone MyCalc 1.0.22 (23).
Reproduction
Evaluate 10^15; then continue with +1 and evaluate.
Expected
A valid numeric continuation (mathematically 1000000000000001 is representable in binary64); at minimum, no parser Error for the displayed finite value.
Observed
Initial display 1e+15; continuation displayed 1e+15+1 and Error.
Evidence
TC-CALC-009, direct APK runtime, shard 3 of run 40321408355; failures were reported for both packages.
Impact
Users cannot continue a calculation from a large result displayed in scientific notation.
Suggested next step
Separate the internal value from its formatted string, support exponent-form input or retain the numeric result internally, and cover the continuation with a boundary regression test.
Regression note
The same TC-009 failure was recorded in the preserved v3.12.21 history report and reproduced again on v3.12.24 / 1.0.22.

DEF-324-03 · Standalone “zero permissions” claim conflicts with PackageManager

OPEN · P3 · CLAIM / MANIFEST

QA comment: The guide says the standalone MyCalc app has “zero permissions.” The exact installed APK's PackageManager dump lists one requested permission: app.space.calc.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION, so the literal zero-requested-permissions claim is inaccurate. The same dump reports prot=signature, granted=true, and an empty runtime-permissions section. This is a documentation/manifest-claim mismatch, not evidence of a dangerous runtime permission prompt. The dependency origin was not traced.

Affected build
Standalone MyCalc 1.0.22 (23), package app.space.calc.
Reproduction
Install the pinned APK on Android 14; inspect dumpsys package app.space.calc under “requested permissions”.
Expected
No requested permissions, as stated in guide section F.
Observed
One requested custom permission: app.space.calc.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION. PackageManager reports prot=signature, granted=true, and no runtime permissions in its runtime-permissions section.
Evidence
TC-CALC-012 result JSON and full PackageManager dump in the published evidence folder; source Android run 40321408355.
Impact
Trust/documentation mismatch. Available evidence identifies a signature-protected custom permission and an empty runtime-permissions section; dependency origin was not traced.
Suggested next step
Inspect the merged release manifest and dependency origin. If the custom permission is required, revise the guide to make a precise claim such as “no runtime permissions” only if that is the intended guarantee; otherwise remove the unneeded request and retain a manifest regression check.
