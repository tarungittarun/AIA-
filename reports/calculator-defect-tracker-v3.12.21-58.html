Blind black-box probes

These extra probes are outside the guide's explicit examples. Expected arithmetic behavior was set from the user-visible expression, without assuming an implementation.

BND-01 · TC-CALC-008

1 ÷ 3 = × 3 = should return exactly 1.

FAIL · MySpace and MyCalc

BND-02 · TC-CALC-009

10^15 = + 1 = should evaluate to 1000000000000001.

FAIL · MySpace and MyCalc

Both display 1e+15+1 followed by Error.

Open defect tracker

DEF-3219-01 · Chained calculation loses precision OPEN · P2 / MEDIUM

Affected builds
MySpace 3.12.21 code 58; MyCalc 1.0.19 code 20
Reproduction
Enter 1 ÷ 3, press equals, append × 3, press equals.
Expected / actual
Expected 1; both APKs display 0.9999999999.
Comment · 2026-10-26
Reproduced on the Android 14 emulator in both checksum-pinned APKs. The same result appeared in the earlier MySpace 3.12.19-56 QA run (40284113631). The first result shown was 0.3333333333. Recurrent runtime defect; not an OCR mismatch.
Root-cause note
Reusing rounded display text is plausible but unconfirmed.
Suggested follow-up
Preserve unrounded numeric state across equals-then-operator input and add an exact-result regression.

DEF-3219-02 · Scientific-notation result cannot be continued OPEN · P2 / MEDIUM

Affected builds
MySpace 3.12.21 code 58; MyCalc 1.0.19 code 20
Reproduction
Enter 10 ^ 15, press equals, append + 1, press equals.
Expected / actual
Expected 1000000000000001 or equivalent; both APKs show 1e+15+1 then Error.
Comment · 2026-10-26
Reproduced on both exact distribution APKs. This is an additional blind edge probe, not a failure of a guide example. The harness's initial “ERROR” classification was corrected to “FAIL” for this visible product error, then the three-shard plan was rerun.
Root-cause note
The parser/validator may reject exponent-formatted result text; this is a hypothesis, not a confirmed diagnosis.
Suggested follow-up
Separate internal numeric state from formatted display text and add an end-to-end continuation test.

Limits and interpretation

  1. The plan covers sections A–G, but exact-APK runtime automation currently covers the calculator only. Other MySpace screens and unautomated visual/gesture claims are not verified by this report.
  2. Guide-reported automated coverage and exact-source CI are green; those are source-level checks and do not prove every supplied APK screen/gesture.
  3. The official Google Calculator was absent. TC-CALC-010 remains blocked; no AOSP substitute or third-party mirror was used.
  4. Standalone MyCalc TC-CALC-006 and TC-CALC-007 were selected but lack standalone per-case evidence in published check annotations; both remain unconfirmed.
  5. No physical handset run, ad inventory audit, or non-calculator MySpace distribution-APK exploration was completed. This QA work changed no app or advertising code.

Recommended next steps

  1. Fix and regress DEF-3219-01 and DEF-3219-02 in the calculator engine; retest both pinned APKs.
  2. Add direct MySpace distribution coverage for B/C/E and each G feature; collect standalone MyCalc outcomes for cases 006–007.
  3. If licensing and runner constraints permit, add the official Google Calculator to a Play-enabled reference environment and rerun TC-CALC-010. Do not substitute AOSP.
